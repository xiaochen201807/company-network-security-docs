# 24 - 移动应用安全

> 本文档用于规范 Android、iOS 和相关移动端 SDK 的安全开发、测试和发布。参考 OWASP MASVS/MAS 项目的控制分类，包括 Storage、Crypto、Auth、Network、Platform、Code、Resilience 和 Privacy。

## 1. 目标

- 移动端不成为敏感数据和令牌泄露入口。
- 客户端与后端认证授权边界清晰。
- 本地存储、网络通信、Deep Link、WebView 等高风险能力统一治理。
- App 包、签名和发布供应链受控。
- 移动安全测试进入发布流程。

## 2. 适用范围

- Android。
- iOS。
- Flutter。
- React Native。
- Hybrid App。
- Mobile SDK。
- 企业内部 App。

## 3. 基本原则

移动端运行环境由用户控制，因此：

- 不能把客户端视为可信。
- 不能只在客户端做授权。
- 不能在 App 中存长期高权限 凭据。
- 服务端必须重新校验关键业务规则。

## 4. MASVS 控制域

参考：

- STORAGE。
- CRYPTO。
- AUTH。
- NETWORK。
- PLATFORM。
- CODE。
- RESILIENCE。
- PRIVACY。

## 5. 本地敏感数据

避免保存：

- 密码。
- 长期 Refresh 令牌（若无安全存储/轮换）。
- 私钥。
- 业务高敏原文。
- Debug 日志。

## 6. 安全存储

### Android
根据风险使用 Android Keystore 等平台能力。

### iOS
根据风险使用 Keychain/Secure Enclave 等能力。

不要使用普通 SharedPreferences/UserDefaults 明文保存高敏凭据。

## 7. 缓存 / 临时文件

检查：

- Screenshot。
- Clipboard。
- Cache。
- Temp File。
- Backup。
- Notification Preview。

避免敏感数据残留。

## 8. 截屏保护

对特别敏感页面按业务风险考虑限制截图/后台任务预览，但要评估用户体验。

## 9. 剪贴板

密码、令牌等高敏数据避免长期放入系统剪贴板。

## 10. 日志

Release App 禁止输出：

- 密码。
- 令牌。
- 凭据。
- 完整敏感业务数据。
- Internal Debug Info。

## 11. 认证

移动端认证必须依赖服务端可信判断。

支持场景：

- Password。
- SSO。
- OAuth/OIDC。
- Biometric。

## 12. 生物识别

指纹/Face ID 更适合作为本地用户存在性验证，不应把客户端返回“验证成功”直接当服务端权限依据。

## 13. 令牌

- 短 Access 令牌。
- Refresh 令牌受保护。
- Logout 可撤销/失效。
- 令牌不写日志。
- 范围最小化。

## 14. 授权

对象级、功能级、数据级授权在服务端执行。反编译 App 后隐藏按钮很容易被绕过。

## 15. 网络

- TLS。
- Hostname Verification。
- 禁止 Release 信任所有证书。
- 禁止关闭证书校验。
- HTTP 明文按平台和业务严格控制。

## 16. 证书绑定（Pinning）

Pinning 根据威胁模型决定。

优点：降低部分 MITM 风险。风险：证书轮换、代理、灾难恢复复杂。

如使用必须设计 Pin Rotation/Backup Pin。

## 17. API

移动 API 同样遵循 06：

- Auth。
- Authorization。
- Rate Limit。
- Replay。
- Business Logic。
- Device 不可信。

## 18. 设备标识

不要把设备 ID 作为唯一安全认证因素。

设备标识可能：

- 被重置。
- 被伪造。
- 受隐私限制。

## 19. Root / 越狱检测

检测 Root/Jailbreak 可以作为风险信号，但不应作为唯一安全控制，因为检测可被绕过。

## 20. WebView

重点：

- 只加载可信内容。
- JavaScript Interface 最小化。
- 禁止不安全文件访问。
- URL Scheme 校验。
- 不把令牌注入不可信页面。

## 21. 深层链接（Deep Link）

验证：

- Scheme/Host。
- 参数。
- 目标页面。
- 身份状态。

不能通过 Deep Link 绕过正常权限流程。

## 22. 通用链接 / App Link

使用平台验证能力，减少任意 App 劫持链接。

## 23. Intent / 进程间通信（IPC）

Android：

- Exported Component。
- Intent Validation。
- PendingIntent。
- ContentProvider。

iOS：

- URL Scheme。
- Universal Link。
- App Extension。

跨 App 数据输入视为不可信。

## 24. 文件安全

移动端打开外部文件：

- Type。
- Size。
- Path。
- Parser。
- Malicious Content。

均需验证。

## 25. 密码学

- 不自研算法。
- 不硬编码主密钥。
- 使用平台 Crypto。
- Nonce/IV 正确。
- Random 使用安全源。

## 26. 硬编码凭据

App 安装包可被反编译。

因此：

- 不放数据库密码。
- 不放服务器私钥。
- 不放长期高权限 API 凭据。

公开客户端所需 Key 必须假设可被获取并限制权限。

## 27. 混淆

混淆可提高逆向成本，但不能替代服务端授权。

## 28. 防篡改

高风险 App MAY 使用：

- Signature Check。
- Integrity API。
- Runtime Protection。

仍假设高级攻击者可能绕过。

## 29. 调试构建

生产 Release：

- Debug 关闭。
- Test Endpoint 移除。
- Mock Data 移除。
- Dev Certificate 不使用。
- Debug Menu 不暴露。

## 30. 源码映射 / 符号文件

发布调试符号和 Source Map 需要按排障、安全和崩溃分析需求控制访问。

## 31. 依赖

移动端第三方 SDK：

- SCA。
- 来源。
- 权限。
- 数据采集。
- 更新。
- License。

## 32. 第三方 SDK

广告、统计、推送 SDK 可能收集数据。

引入前评估：

- 权限。
- 数据。
- 网络域名。
- Provider。
- 更新机制。

## 33. 权限

App 只申请必要系统权限：

- Camera。
- Location。
- Contacts。
- Storage。
- Bluetooth。
- Microphone。

不用的权限删除。

## 34. 隐私

明确：

- 收集什么。
- 为什么。
- 何时请求权限。
- 用户如何撤回。
- 本地/远端如何删除（按业务与适用要求）。

## 35. 应用签名

Android/iOS 发布签名 Key：

- 高等级保护。
- 不放普通开发电脑。
- 权限最小化。
- 备份/恢复。
- 使用审计。

## 36. CI/CD

移动构建：

- Ephemeral Runner（成熟阶段）。
- Signing Key 受控。
- Artifact Hash。
- SAST/SCA/凭据。
- Build 可追溯。

## 37. 应用商店发布

发布前：

- 版本。
- Build。
- Signing。
- Security Scan。
- Privacy。
- Release Note。
- Rollback/Hotfix Plan。

## 38. 移动应用安全测试

至少覆盖：

- Storage。
- Auth。
- Network。
- Deep Link。
- WebView。
- IPC。
- Hardcoded 凭据。
- Debug。
- API。
- Business Logic。

## 39. 设备测试实验室

可建设测试环境：

- Android 多版本。
- iOS 多版本。
- Root/Jailbreak Test Device。
- Proxy。
- Dynamic Analysis。

## 40. 移动应用渗透测试

核心 App 重大版本或高风险变化 SHOULD 进行授权移动安全测试。

## 41. 后端依赖

很多移动风险根源在后端 API。

移动测试必须同时验证后端授权和业务逻辑。

## 42. 运行时威胁

根据业务可检测：

- Tampered App。
- Root/Jailbreak。
- Emulator。
- Hooking。
- Automation。

这些信号用于风险判断，不可单独作为核心认证。

## 43. 欺诈 / 滥用

公众 App 关注：

- Emulator Farm。
- Device Farm。
- Registration Abuse。
- Coupon Abuse。
- Credential Stuffing。
- Bot。

## 44. 度量

- App SAST/SCA 覆盖率。
- Mobile Pentest 覆盖率。
- Hardcoded 凭据 数量。
- 过度权限数量。
- Release Debug Issue。
- SDK 风险数量。
