# 04 - 身份与访问控制

> 本文档用于规范人员账号、服务账号、管理员权限、MFA、凭据、访问审批、权限复核和账号生命周期，确保“正确的人，在正确的时间，以正确的权限，访问正确的资源”。

## 1. 目标

- 一人一号，身份可追溯。
- 权限按业务需要最小化。
- 高权限访问受控、可审计。
- 离职和转岗权限及时变化。
- 密码、Token、Key 等凭据集中治理。
- 关键系统逐步统一身份和 MFA。

## 2. 身份类型

公司至少区分：

- 员工账号
- 外包/供应商账号
- 管理员账号
- 服务账号
- API Token
- CI/CD Token
- SSH Key
- 紧急 Break-glass 账号

不同类型不得混用用途。

## 3. 账号生命周期

~~~text
入职/创建 → 权限申请 → 审批 → 开通
→ 使用 → 定期复核 → 转岗变更
→ 离职/到期 → 禁用 → 删除/归档
~~~

## 4. 入职与创建

**MUST：**

- 基于实名身份创建。
- 默认只开通基础权限。
- 生产、高权限、敏感数据权限单独审批。
- 禁止提前创建长期无人使用账号。

## 5. 转岗

转岗时重新评估：

- Git/Git 管理权限
- Jenkins
- VPN
- 生产环境
- 数据库
- 云平台
- 业务后台
- 敏感数据

原则：

> 先回收旧岗位不再需要的权限，再增加新权限。

## 6. 离职

离职或合同终止时：

- 禁用统一账号。
- 禁用 VPN。
- 回收 Git/Jenkins/云权限。
- 回收 SSH Key、Token 和证书。
- 转移系统 Owner。
- 回收设备。
- 处理个人创建的服务账号或自动化任务。

**MUST：高权限和远程访问权限应在离职生效时及时失效。**

## 7. 一人一号

禁止多人共享管理员账号。

确实无法避免的技术账号必须：

- 记录用途。
- 限制登录来源。
- 通过密码库/PAM 管理。
- 有使用审计。
- 定期轮换凭据。

## 8. RBAC 与最小权限

权限优先按角色授予，避免大量用户直接绑定零散权限。

角色设计应避免：

- “超级管理员”成为默认角色。
- 普通开发拥有生产全权限。
- 只读人员拥有写/删除权限。
- 项目结束后权限长期保留。

## 9. 职责分离

高风险流程 SHOULD 分离：

- 申请与审批
- 开发与生产发布审批
- 数据导出与审批
- 安全例外申请与最终批准
- 管理员授权与审计

## 10. MFA

优先启用范围：

- VPN
- 云平台
- Git 管理员
- Jenkins 管理员
- 邮箱/统一身份
- PAM/堡垒机
- 对公网管理后台
- 其他关键 SaaS

**SHOULD：关键管理面 MFA 覆盖率接近 100%。**

## 11. SSO

如果具备统一身份平台，SHOULD 优先将关键系统接入 SSO，以便集中执行：

- 离职禁用
- MFA
- 密码策略
- 登录审计
- 风险登录检测

无法接入 SSO 的系统应纳入独立账号台账。

## 12. 密码策略

密码策略应兼顾强度与可用性：

- 禁止默认密码。
- 禁止已泄露/常见弱密码。
- 管理员使用高强度凭据。
- 系统支持时启用登录失败保护。
- 不要求用户通过可预测方式频繁改密码。
- 有泄露迹象时立即重置/吊销。

具体复杂度与周期根据公司身份平台和风险确认。

## 13. Secret 管理

禁止在以下位置明文保存长期 Secret：

- Git
- Jenkinsfile
- Shell 脚本
- Wiki
- 聊天群
- 工单正文
- Excel 明文表格

优先使用：

- Secret Manager
- Vault
- Jenkins Credentials
- Kubernetes Secret + 合适加密/权限
- 云密钥管理服务

## 14. 凭据泄露

发现密码、Token、私钥泄露：

1. 立即吊销或禁用。
2. 生成新凭据。
3. 更新使用方。
4. 检查日志。
5. 清理传播位置。
6. 必要时启动事件响应。

仅删除泄露文本不足以消除风险。

## 15. 服务账号

服务账号必须：

- 有 Owner。
- 有明确用途。
- 最小权限。
- 原则上禁止交互式登录。
- 凭据可轮换。
- 不与个人账号共用。
- 应用下线时同步回收。

## 16. API Token

Token 应：

- 明确 Scope。
- 明确有效期。
- 明确 Owner。
- 可吊销。
- 可轮换。
- 不授予超出用途的权限。

尽量避免永久有效的全权限 Token。

## 17. SSH Key

SSH Key 管理：

- 一人一 Key 或明确归属。
- 禁止共享私钥。
- 私钥加密保护。
- 离职/设备丢失及时吊销。
- 服务器 authorized_keys 定期检查。
- 自动化 Key 与个人 Key 分离。

## 18. 特权账号

重点包括：

- root
- Administrator
- Domain Admin
- 数据库 root/superuser
- 云管理员
- Git/Jenkins 管理员
- Kubernetes cluster-admin

特权账号要求：

- 与普通账号分离。
- MFA/强认证。
- 使用有审批。
- 操作有日志。
- 权限定期复核。

## 19. sudo / 提权

Linux 推荐普通账号登录后按需 sudo。

重点记录：

- 谁提权
- 时间
- 命令
- 目标主机

禁止无业务原因的 NOPASSWD ALL 长期配置。

## 20. PAM 与 JIT

成熟阶段 SHOULD 引入：

- PAM：特权账号集中管理。
- JIT：临时授予高权限。
- Session Recording：高权限会话审计。
- Approval Workflow：高风险操作审批。

## 21. Break-glass 紧急账号

紧急账号用于身份系统故障等特殊场景。

必须：

- 严格限制人数。
- 凭据高强度并安全封存。
- 平时不使用。
- 使用触发告警。
- 使用后立即审计并轮换。

## 22. 登录会话安全

应用与管理平台应合理控制：

- Session 超时
- Token 有效期
- 注销失效
- 高风险操作二次认证
- 并发 Session（按业务需要）
- 异常登录检测

## 23. 权限申请

权限申请至少记录：

| 字段 | 内容 |
|---|---|
| 申请人 | |
| 系统 | |
| 权限角色 | |
| 业务原因 | |
| 环境 | |
| 开始/到期时间 | |
| 审批人 | |

生产高权限 SHOULD 设置到期时间。

## 24. 权限复核

### 每月/季度重点
- 管理员
- VPN
- 生产
- 数据库
- 云平台
- Git/Jenkins
- 外包

复核结果：

- 保留
- 降权
- 回收
- 设置有效期

## 25. 外包与第三方账号

必须：

- 实名。
- 标记外部身份。
- 有合同/项目结束日期。
- 最小权限。
- 到期复审或自动失效。
- 不使用离职员工账号“接着用”。

## 26. 默认与僵尸账号

重点清理：

- 默认账号
- 测试账号
- 长期未登录账号
- 无 Owner 服务账号
- 历史外包账号
- 过期管理员账号

## 27. 认证日志

至少采集：

- 登录成功/失败
- MFA 结果
- 密码修改
- Token 创建/吊销
- 管理员权限变更
- 账号启用/禁用
- 高权限操作

## 28. 检测场景

- 暴力破解
- 密码喷洒
- 异常来源登录
- 短时间多地登录
- 新增管理员
- Break-glass 使用
- 离职账号登录
- 服务账号交互登录
- Token 异常使用

## 29. 指标

- MFA 覆盖率
- 高权限账号数
- 无 Owner 服务账号数
- 共享账号数
- 离职及时回收率
- 过期外包账号数
- 权限复核完成率

## 30. 检查频率

### 每周
- [ ] 新增管理员
- [ ] 离职账号
- [ ] 异常登录
- [ ] Break-glass 使用

### 每月
- [ ] 高权限清单
- [ ] 服务账号
- [ ] 长期未登录账号
- [ ] 外包账号到期
- [ ] Token/SSH Key 风险

### 每季度
- [ ] 生产权限全面复审
- [ ] VPN 权限复审
- [ ] Git/Jenkins 权限复审
- [ ] 数据库管理员复审

## 31. 落地路线

### P0
一人一号、离职回收、管理员清单、VPN/关键系统 MFA、服务账号 Owner、共享账号清理。

### P1
SSO、权限定期复核、Token 有效期、Secret 平台、生产权限到期。

### P2
PAM、JIT、行为分析、自动化权限治理。

## 32. 审计证据

账号清单、权限申请、审批、权限复核、登录日志、管理员变更、离职回收、Token/Key 台账和 Break-glass 使用记录。
