# 07 - 数据安全

> 本文档用于规范数据从采集、传输、存储、使用、共享、导出、备份、归档到删除的全生命周期安全要求。具体法律、监管、客户合同与行业要求由公司法务/合规根据实际适用范围确认，本章不假定公司当然适用某一特定法规。

## 1. 目标

- 明确数据在哪里、由谁负责、敏感程度如何。
- 数据访问与业务目的匹配，遵循最小权限。
- 敏感数据传输、存储和备份获得适当保护。
- 导出、共享和第三方使用可审批、可追溯。
- 测试、日志、备份等容易被忽略的副本同样受保护。
- 数据泄露、误传和异常访问能够被检测与响应。

## 2. 适用范围

- 数据库
- Redis/缓存
- MQ/消息
- Elasticsearch/搜索索引
- 对象存储/文件
- 日志
- 数据仓库/报表
- 备份
- 开发测试数据
- Excel/CSV 导出文件
- 第三方交换数据
- SaaS 中保存的数据

## 3. 控制级别

- **MUST**：强制要求。
- **SHOULD**：应尽量实施。
- **MAY**：增强要求。

## 4. 数据 Owner

关键数据集必须有业务 Owner。Owner 负责确认数据用途、分类、访问范围、共享对象、保留周期和风险接受。

## 5. 数据分类分级

公司可采用四级模型作为起点：

| 等级 | 示例 | 原则 |
|---|---|---|
| 公开 | 官网公开内容 | 可公开传播 |
| 内部 | 一般内部资料 | 限公司内部 |
| 敏感 | 用户信息、合同、业务明细 | 严格授权与审计 |
| 核心/高度敏感 | 核心密钥、关键业务数据 | 最严格保护 |

最终分类应结合业务和适用要求确认。

## 6. 数据识别

SHOULD 建立敏感数据目录，至少回答：

- 数据名称
- 系统/库/表/字段
- 数据 Owner
- 分类级别
- 是否包含个人/客户/财务/认证类信息
- 生产/测试分布
- 备份位置
- 第三方共享

## 7. 数据最小化

业务只采集和保存完成业务目的所需的数据。避免“以后可能有用”而无限制采集敏感信息。

## 8. 数据采集

- 明确采集目的。
- 避免收集无关敏感字段。
- 前端输入只收必要字段。
- 不把 Secret、密码等作为普通业务数据长期保存。

## 9. 数据传输

敏感数据跨不可信网络传输 SHOULD 使用 TLS 或其他适当保护。

内部敏感链路根据风险评估 TLS/mTLS。禁止通过未批准的个人邮箱、网盘、聊天工具大量传输敏感数据。

## 10. 数据存储

敏感数据存储应根据风险使用：

- 数据库访问控制
- 字段/列级加密
- 磁盘/存储加密
- Tokenization
- Hash
- 密钥管理

加密不是权限控制的替代品。

## 11. 密码与认证数据

- 用户密码不得明文存储。
- 使用成熟密码哈希算法。
- API Key/Token/私钥应进入 Secret 管理体系。
- 不在数据库普通字段、日志、报表中保存明文凭据。

## 12. 数据库账号

### 12.1 应用账号

- 不使用 root/superuser。
- 只授予所需库表和操作权限。
- 不与管理员账号共用。
- Secret 可轮换。

### 12.2 管理账号

- 实名或通过 PAM 追溯。
- 强认证。
- 高风险操作审计。
- 定期复核。

## 13. 数据库网络

生产数据库 MUST 不无保护公网暴露。只允许必要应用和管理来源访问。

## 14. 高风险数据库操作

重点审计：

- DROP/TRUNCATE
- 大批量 DELETE/UPDATE
- 权限变更
- 创建高权限账号
- 大规模 SELECT/导出
- 修改审计配置

## 15. Redis / 缓存

- 不公网暴露。
- 认证/ACL。
- Key 不包含不必要明文敏感信息。
- 敏感缓存设置合理 TTL。
- 多租户 Key 隔离。
- 权限变化时考虑缓存失效。

## 16. Elasticsearch

- 开启认证授权。
- 索引权限最小化。
- 管理接口限制来源。
- 快照安全保存。
- 日志和检索结果避免不必要泄露敏感字段。

## 17. MQ

- Topic/Queue 权限最小化。
- 敏感消息根据风险加密。
- 消息中避免携带长期 Secret。
- 消费者日志不打印完整敏感 Payload。

## 18. 对象存储

- Bucket 默认私有。
- 公共访问必须有明确业务原因。
- 临时 URL 设置合理有效期。
- AccessKey 最小权限并可轮换。
- 重要 Bucket 开启访问日志/版本保护（按平台能力）。

## 19. 文件系统

敏感文件：

- 权限最小化。
- 不放 Web Root 可直接下载。
- 临时文件及时删除。
- 文件名避免暴露不必要业务信息。
- 备份与副本同样保护。

## 20. 日志数据

日志是常见的敏感数据泄露来源。

**MUST：不得无必要记录：**

- 密码
- 完整 Token
- 私钥
- Authorization Header
- 完整身份证件/银行卡等敏感字段
- 数据库完整连接 Secret

必要字段采用掩码或部分显示。

## 21. 脱敏

常见方式：

- Masking
- Tokenization
- Hash
- 截断
- 泛化
- 匿名化/假名化

脱敏方式应与使用场景和重新识别风险匹配。

## 22. 测试数据

原则上测试环境不直接使用完整生产敏感数据。

如确需使用：

- 有审批。
- 最小数据集。
- 脱敏。
- 测试环境访问受控。
- 到期清理。

## 23. 数据导出

高风险导出必须：

- 校验权限。
- 限制数据范围。
- 记录导出人、时间、条件、数量。
- 大量导出按风险审批。
- 导出文件设置生命周期。

不能因为用户有查询权限就默认允许无限量导出。

## 24. 报表

报表系统应遵循与源系统一致或更严格的数据权限。缓存报表和下载文件同样是敏感数据。

## 25. 数据共享

跨部门或第三方共享前明确：

- 目的
- 字段
- 数据量
- 频率
- 传输方式
- 保存期限
- 接收方
- 退出/删除方式

只共享完成目的所需的最少数据。

## 26. 第三方数据处理

重要第三方应明确：

- 可访问数据范围
- 安全责任
- 数据存放位置和方式（按实际需要）
- 子处理方
- 安全事件通知
- 合作结束后的返还/删除

具体合同条款由法务/采购/安全共同确认。

## 27. 数据保留

不同数据类型应有保留期限。到期后删除、归档或匿名化，而不是无限期保存。

保留策略同时覆盖：

- 主库
- 历史库
- 日志
- 对象存储
- 导出文件
- 备份

## 28. 数据删除

删除应考虑所有副本和合理技术边界。逻辑删除不必然等于数据真正不可访问。

系统下线时必须制定数据迁移、归档和销毁方案。

## 29. 备份

备份中的敏感数据保护等级不应低于生产数据。

- 备份访问与生产权限适当隔离。
- 重要备份加密或采取等效保护。
- 恢复过程有审计。
- 定期恢复测试。
- 过期备份按策略销毁。

## 30. 密钥管理

### MUST

- 密钥与业务数据分离。
- 禁止在代码中长期硬编码生产密钥。
- 限制访问。
- 支持轮换。
- 泄露时可吊销。

### SHOULD

使用 KMS/HSM/Secret Manager 等集中能力。

## 31. 加密算法

使用成熟标准算法和库，不自行设计密码算法。禁止继续新增明显过时或已知不安全的算法用于敏感保护。

## 32. 数据完整性

对高价值数据根据场景使用：

- 数据库约束
- Hash/MAC
- 数字签名
- 版本控制
- 审计日志

防止未经授权修改。

## 33. 数据访问审计

高敏数据访问 SHOULD 能回答：

- 谁访问
- 什么时间
- 哪个系统
- 什么数据范围
- 做了什么操作
- 是否成功

## 34. 异常数据访问检测

重点检测：

- 短时间大量查询
- 大量导出
- 非工作时间高风险访问
- 管理员批量读取
- 异常来源访问
- 账号首次访问高敏数据

## 35. 数据泄露事件

出现误发、公开 Bucket、Secret 泄露、大量异常导出等情况时，应进入事件响应流程，评估：

- 暴露数据类型
- 数量
- 时间范围
- 可访问人员
- 是否被下载
- 是否需要吊销凭据
- 是否存在适用的通知义务（由法务/合规判断）

## 36. 数据变更与删除审批

核心数据的大批量修改、删除或结构变更 SHOULD 有变更审批、备份/回退和执行验证。

## 37. 开发人员数据权限

开发人员原则上不长期持有生产数据库高权限。排障访问按需、限时、审计。

## 38. 数据管理员职责

数据库管理员与数据 Owner 职责分离：DBA 管理技术平台，业务 Owner 决定数据业务授权。

## 39. 数据发现与 DLP

成熟阶段可建设：

- 敏感数据自动发现
- 数据标签
- DLP
- 邮件/终端外发控制
- 异常数据访问分析

## 40. 指标

- 已分类核心系统比例
- 高敏数据集 Owner 覆盖率
- 数据库高权限账号数
- 测试环境生产数据违规数
- 大量导出告警数
- 公开对象存储风险数
- 敏感日志问题数
- 备份恢复成功率

## 41. 检查频率

### 每周
- [ ] 异常大批量导出
- [ ] 公开对象存储变化
- [ ] Secret/敏感日志告警

### 每月
- [ ] 数据库高权限账号
- [ ] 测试数据使用
- [ ] 数据导出审计
- [ ] 备份失败

### 每季度
- [ ] 高敏数据权限复核
- [ ] 数据分类更新
- [ ] 第三方共享复审
- [ ] 保留和删除策略抽查

## 42. 落地路线

### P0
核心数据库清单、数据 Owner、数据库最小权限、日志脱敏、导出审计、测试数据规范、备份恢复。

### P1
分类分级、KMS/Secret、敏感数据发现、对象存储检查、第三方共享台账。

### P2
DLP、细粒度数据访问治理、异常数据访问分析、自动保留/销毁。

## 43. 审计证据

数据目录、权限审批、数据库账号、导出记录、第三方共享审批、脱敏规则、密钥记录、备份恢复、数据销毁记录。
