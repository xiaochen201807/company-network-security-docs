# 14 - 安全基线与检查清单

> 本文档将前述安全要求转化为可直接执行的检查清单。基线用于发现偏差，不应在不了解业务影响的情况下自动修改生产配置。具体参数值应结合产品版本、公司架构和性能要求确认。

## 1. 目标

- 建立统一的日/周/月/季度安全检查。
- 为 Windows、Linux、Nginx、Tomcat、JDK/JVM、数据库、Redis、Elasticsearch、Jenkins、Git、Maven/Nexus、Docker、Kubernetes、Spring Boot、API Gateway、VPN、防火墙、WAF 建立基础检查项。
- 每个不符合项有风险等级、Owner、截止时间和复测。
- 基线结果可度量、可审计。

## 3. 基线例外

无法满足 MUST 基线时走安全例外，记录原因、补偿控制、风险 Owner、审批和到期时间。不能通过把检查项删除来隐藏偏差。

## 4. 每日检查

- [ ] P1/P2 安全告警
- [ ] EDR 严重告警与离线资产
- [ ] Critical 漏洞
- [ ] 核心异常登录
- [ ] 备份失败
- [ ] 关键安全设备异常
- [ ] 大面积日志源离线

## 5. 每周检查

- [ ] 公网资产变化
- [ ] High 漏洞整改
- [ ] Git/Jenkins 管理员变化
- [ ] VPN 异常登录
- [ ] 临时防火墙规则到期
- [ ] 新增高风险端口
- [ ] 重要安全公告影响
- [ ] 安全例外即将到期

## 6. 每月检查

- [ ] 资产台账与扫描对账
- [ ] 主机补丁
- [ ] Linux/Windows 基线
- [ ] SCA 全量复查
- [ ] Secret Scan
- [ ] 数据库高权限
- [ ] 日志覆盖率
- [ ] 证书到期
- [ ] 备份恢复抽测
- [ ] 防火墙/VPN 抽查
- [ ] 中间件版本/EOL

## 7. 每季度检查

- [ ] 生产权限全面复审
- [ ] 公网暴露面评估
- [ ] 核心系统漏洞/渗透测试计划
- [ ] 防火墙规则全面复审
- [ ] 安全基线全量扫描
- [ ] 应急演练
- [ ] 容灾/恢复演练
- [ ] 第三方连接复审
- [ ] 核心数据权限复审

## 8. Windows 基线

### 8.1 账号
- [ ] Guest 等无用账号禁用。
- [ ] 本地管理员成员符合审批。
- [ ] 无离职/未知管理员。
- [ ] 服务账号用途和 Owner 明确。

### 8.2 认证
- [ ] 密码策略符合公司标准。
- [ ] 登录失败保护合理。
- [ ] RDP 不公网直接暴露。
- [ ] 远程管理使用受控路径。

### 8.3 补丁与版本
- [ ] OS 处于支持期。
- [ ] 高风险补丁未超期。
- [ ] 不存在长期关闭更新且无例外。

### 8.4 EDR
- [ ] EDR/Defender 正常运行。
- [ ] Agent 在线。
- [ ] 防护未被普通用户关闭。

### 8.5 日志
- [ ] Security/System 日志可用。
- [ ] PowerShell 日志按公司策略启用。
- [ ] RDP、管理员变化等日志集中。

### 8.6 主机保护
- [ ] 主机防火墙按策略启用。
- [ ] SMB 无不必要旧协议/公开共享。
- [ ] 不存在未知远控软件。
- [ ] 终端磁盘加密按公司策略启用。

## 9. Linux 基线

### 9.1 账号
- [ ] 无未知 UID 0 账号。
- [ ] 离职/无 Owner 账号清理。
- [ ] 服务账号不无必要交互登录。

### 9.2 SSH
- [ ] 不公网无保护暴露。
- [ ] 禁止弱口令。
- [ ] root 直接登录符合公司策略。
- [ ] 来源限制合理。
- [ ] 使用安全算法和协议。

### 9.3 sudo
- [ ] sudoers 权限最小化。
- [ ] 无无理由 NOPASSWD ALL。
- [ ] sudo 操作有日志。

### 9.4 文件
- [ ] shadow/SSH Key/私钥权限正确。
- [ ] 应用配置中的 Secret 不对无关用户可读。
- [ ] 临时目录不存在高风险敏感文件。

### 9.5 服务
- [ ] 监听端口与资产台账一致。
- [ ] 未知服务已调查。
- [ ] 不需要的服务关闭。

### 9.6 补丁
- [ ] OS 受支持。
- [ ] Critical/High 补丁未超 SLA。

### 9.7 日志与 EDR
- [ ] SSH/sudo/system 日志集中。
- [ ] EDR/主机安全 Agent 在线。
- [ ] 时间同步正常。

## 10. Nginx 基线

- [ ] 使用公司批准且受支持版本。
- [ ] 非必要不暴露详细版本。
- [ ] TLS 配置符合公司标准。
- [ ] 私钥文件权限受控。
- [ ] 管理/状态接口限制来源。
- [ ] Access/Error 日志启用并集中。
- [ ] 上传大小有合理限制。
- [ ] 请求/上游超时合理。
- [ ] 反向代理客户端 IP Header 只信任受控代理。
- [ ] 不存在无业务理由的目录列表。
- [ ] 配置变更有版本/备份和回退。

## 11. Tomcat 基线

- [ ] 使用受支持版本。
- [ ] Manager/Host Manager 无需要则删除或禁用。
- [ ] 管理应用不公网暴露。
- [ ] 默认示例应用按需要清理。
- [ ] 应用运行账号非 root。
- [ ] server.xml/context.xml 权限受控。
- [ ] AJP/管理端口按需要启用且限制来源。
- [ ] 错误页面不泄露敏感堆栈。
- [ ] Access/Catalina 日志接入。
- [ ] JVM 启动参数受控。

## 12. JDK / JVM 基线

- [ ] JDK 处于安全支持期或有升级计划。
- [ ] 不使用已明确淘汰且无支持的生产版本。
- [ ] JMX 不公网无认证暴露。
- [ ] Debug 端口不公网暴露。
- [ ] Heap Dump/Core Dump 作为敏感数据保护。
- [ ] JVM 启动参数纳入版本/配置管理。
- [ ] Heap、GC、Thread、CPU 有监控。
- [ ] Full GC/Old Gen 异常有告警。
- [ ] 时区、编码等关键参数标准化。

## 13. MySQL / PostgreSQL 基线

- [ ] 数据库不公网直接暴露。
- [ ] 应用账号不使用 root/superuser。
- [ ] 管理员账号可追溯。
- [ ] 默认/测试账号清理。
- [ ] 来源地址最小化。
- [ ] 高风险 DDL/DCL/大批量操作有审计。
- [ ] 备份成功并做恢复测试。
- [ ] 复制/主从状态监控。
- [ ] 慢查询和连接数监控。
- [ ] 配置/凭据文件权限正确。
- [ ] 数据库版本处于支持期。

## 14. Redis 基线

- [ ] 不公网暴露。
- [ ] 开启认证/ACL。
- [ ] bind/网络范围最小化。
- [ ] 默认/弱凭据清理。
- [ ] 管理/高风险命令按业务限制。
- [ ] 数据目录权限受控。
- [ ] 持久化/备份策略明确。
- [ ] 内存、水位、连接、延迟监控。
- [ ] 大 Key/热 Key 有治理。
- [ ] 版本处于支持期。

## 15. Elasticsearch 基线

- [ ] 不无认证公网暴露。
- [ ] 认证与角色权限启用。
- [ ] 管理 API 来源限制。
- [ ] 索引权限最小化。
- [ ] 敏感数据访问受控。
- [ ] 快照备份可用。
- [ ] 集群健康、磁盘、水位监控。
- [ ] TLS 按部署风险启用。
- [ ] 默认/历史高权限账号清理。

## 16. Jenkins 基线

- [ ] Controller 不公网无保护暴露。
- [ ] 管理员名单最小化。
- [ ] 管理员 MFA/强认证。
- [ ] 禁止共享管理员账号。
- [ ] Credentials 不明文写 Pipeline。
- [ ] 日志不会打印 Secret。
- [ ] 插件安装权限受控。
- [ ] 插件和 Jenkins Core 安全更新。
- [ ] Script Console 等高危功能严格限制。
- [ ] Agent 与高权限资源适当隔离。
- [ ] Docker Socket 不无差别提供给 Job。
- [ ] 构建产物可追溯 Commit/Build。
- [ ] Jenkins 配置有备份。

## 17. Git 平台基线

- [ ] 管理员名单最小化。
- [ ] 管理员 MFA。
- [ ] main/master/release 等主分支保护。
- [ ] 普通开发不能 force push 受保护分支。
- [ ] 合并需要 Review。
- [ ] 仓库公开范围受控。
- [ ] Token 有 Scope、Owner、有效期。
- [ ] 离职账号及时禁用。
- [ ] 审计登录、权限、Token、仓库可见性变化。
- [ ] 关键仓库备份/恢复策略明确。

## 18. Maven / Nexus / Artifactory 基线

- [ ] 公司 Java 项目优先通过私服拉取依赖。
- [ ] 外部仓库来源受控。
- [ ] Release 仓库原则上不可覆盖。
- [ ] 普通开发无正式仓库删除权限。
- [ ] 上传账号与读取账号按用途分离。
- [ ] 管理员最小化。
- [ ] settings/凭据不进代码。
- [ ] 私服版本和插件及时安全更新。
- [ ] 关键制品保存 Hash。
- [ ] 存储容量和备份监控。

## 19. Docker 基线

- [ ] Docker daemon 不公网无认证暴露。
- [ ] docker.sock 严格限制。
- [ ] 基础镜像来自批准来源。
- [ ] 镜像固定明确版本/摘要策略。
- [ ] 镜像进入生产前扫描。
- [ ] 容器非必要不 root。
- [ ] 非必要不 privileged。
- [ ] Capability 最小化。
- [ ] 不挂载敏感宿主目录。
- [ ] Secret 不写入镜像层。
- [ ] 宿主机和 Docker 版本及时更新。
- [ ] Registry 凭据最小权限。

## 20. Kubernetes 基线

- [ ] Kubernetes 版本处于支持范围。
- [ ] API Server 不无保护公网暴露。
- [ ] RBAC 最小权限。
- [ ] cluster-admin 极少且定期复审。
- [ ] ServiceAccount 权限最小化。
- [ ] Secret 存储与访问受控。
- [ ] 非必要禁止 privileged。
- [ ] 非必要禁止 hostNetwork/hostPID/hostPath。
- [ ] SecurityContext 明确。
- [ ] 容器非必要不 root。
- [ ] NetworkPolicy 按风险实施。
- [ ] Ingress TLS 和管理接口受控。
- [ ] Admission/Policy 能力按成熟度启用。
- [ ] Audit Log 接入。
- [ ] etcd/控制面备份与恢复方案明确。

## 21. Spring Boot 基线

- [ ] Spring/Spring Boot 版本处于支持/治理范围。
- [ ] Actuator 只开放必要 Endpoint。
- [ ] env/heapdump/configprops 不无保护公网暴露。
- [ ] Swagger/OpenAPI 按生产策略开放。
- [ ] 错误响应不泄露堆栈。
- [ ] CORS 有明确白名单。
- [ ] SecurityFilterChain/permitAll 已 Review。
- [ ] JWT/Session 遵循公司安全标准。
- [ ] Secret 不硬编码。
- [ ] SAST/SCA/Secret Scan 完成。
- [ ] 日志不含密码/Token。
- [ ] 外部调用有超时和有限重试。

## 22. API Gateway 基线

- [ ] 管理面不公网无保护暴露。
- [ ] TLS 配置符合标准。
- [ ] 认证策略明确。
- [ ] Route 变更有审计。
- [ ] Rate Limit 策略覆盖高风险接口。
- [ ] IP 白名单/黑名单有 Owner。
- [ ] Access Log 接入。
- [ ] 不在配置中明文保存长期 Secret。
- [ ] Header 转发策略避免信任任意客户端伪造源 IP。

## 23. VPN 基线

- [ ] 一人一号。
- [ ] 外包账号有效期。
- [ ] 离职及时回收。
- [ ] 管理/高风险访问 MFA。
- [ ] VPN 后访问范围最小化。
- [ ] 不默认开放整个内网。
- [ ] 登录成功/失败日志集中。
- [ ] VPN 软件/网关版本及时安全更新。
- [ ] 管理控制台来源限制。

## 24. 防火墙基线

- [ ] 默认拒绝跨区访问。
- [ ] 规则有 Owner/用途。
- [ ] 临时规则有到期时间。
- [ ] any-any 最小化。
- [ ] 公网管理端口受控。
- [ ] 过期/无流量规则定期清理。
- [ ] 管理员实名且最小化。
- [ ] 配置有备份。
- [ ] 管理日志接入。
- [ ] 规则变更有审批和验证。

## 25. WAF 基线

- [ ] 管理面受控。
- [ ] 规则/策略变更有审计。
- [ ] 核心站点已纳管。
- [ ] TLS/证书正常。
- [ ] 高危规则启用前测试。
- [ ] 误报有反馈机制。
- [ ] 白名单最小化且有到期复审。
- [ ] WAF 日志接入 SIEM/日志平台。
- [ ] WAF 不被当作应用漏洞永久修复替代品。

## 26. 基线自动化

SHOULD 逐步通过配置管理、API、脚本、CSPM/KSPM、主机基线工具等自动检查，减少人工截图。

自动化检查必须：

- 版本化规则。
- 记录工具版本。
- 支持例外。
- 保留原始结果。
- 修复后可复测。

## 27. 基线风险等级

建议：

- Critical：直接公网高危暴露、默认/无认证核心服务等。
- High：高权限、严重补丁、关键保护失效。
- Medium：重要配置偏差。
- Low：增强类要求。

最终等级结合资产环境调整。

## 28. 基线整改

~~~text
发现 → 验证 → 定级 → Owner → 整改
→ 变更验证 → 复测 → 关闭
~~~

与 09 漏洞管理可使用同一整改平台。

## 29. 指标

- 基线覆盖率
- 合规率
- Critical/High 偏差数
- 超期偏差数
- 重复偏差数
- 自动检查比例
- 复测通过率

## 30. 落地路线

### P0
先覆盖 Linux、Windows、Nginx、Tomcat、JDK、数据库、Redis、Jenkins、Git 和 VPN。

### P1
覆盖 Docker、Kubernetes、Nexus、Elasticsearch、Spring Boot、WAF/API Gateway，并自动化月度扫描。

### P2
配置即代码、持续控制监控、自动生成整改任务、部分低风险偏差自动修复。

## 31. 审计证据

基线规则版本、扫描报告、原始配置、整改工单、例外、复测、趋势 Dashboard。
