# 02 - 资产与网络架构

> 安全工作的第一步是知道：有什么资产、在哪里、谁负责、承载什么业务和数据、对谁暴露。

## 1. 目标

实现资产可发现、有 Owner、公网暴露可见、关键依赖可见、网络信任边界清晰、关键数据流清晰，以及新增/下线资产及时同步。

## 2. 资产范围

至少纳管：

- 服务器、虚拟机、云主机
- 办公终端、管理终端
- 防火墙、WAF、VPN、交换机、负载均衡
- Web、API、Java 服务、定时任务
- 数据库、Redis、MQ、Elasticsearch、对象存储
- Git、Jenkins、SonarQube、Nexus/Artifactory、Registry、Kubernetes
- 域名、子域名、公网 IP、证书
- SaaS、第三方 API、供应商系统和第三方连接

## 3. 资产唯一标识

建议使用稳定 Asset ID，例如 AST-SRV-000001、AST-APP-000001、AST-DB-000001。名称变化时 ID 尽量保持不变。

## 4. 资产台账字段

| 字段 | 说明 |
|---|---|
| Asset ID | 唯一编号 |
| 名称/类型 | 系统、主机、DB 等 |
| 环境 | 生产/预发布/测试/开发 |
| IP/域名 | 如适用 |
| Owner | 系统负责人 |
| 技术负责人 | 研发/运维 |
| 业务等级 | 核心/重要/一般 |
| 数据等级 | 敏感性 |
| 网络区域 | 办公/生产/DB/DMZ 等 |
| 公网暴露 | 是/否 |
| OS/组件版本 | 主机/中间件 |
| 日志接入 | 是/否 |
| 备份 | 是/否 |
| 最近扫描 | 日期 |
| 生命周期 | 在用/待下线/已下线 |

**MUST：生产资产必须有明确 Owner。**

## 5. 资产发现来源

综合使用 CMDB、云平台、VMware、IP 扫描、DNS、证书清单、防火墙日志、Kubernetes、Jenkins、Git、EDR/Agent 和人工登记。单一来源通常不能覆盖全部资产。

## 6. 新资产准入

上线前至少确认：

- Owner
- 环境与网络区域
- 开放端口
- 公网暴露
- 日志与监控
- 漏洞扫描
- 备份
- 数据等级
- 管理方式

## 7. 资产变更

IP、域名、Owner、环境、公网暴露、数据等级、技术栈变化时应同步台账。

## 8. 资产下线

同时处理 DNS、公网 IP、防火墙规则、VPN、服务账号、Token、证书、监控、扫描任务、备份保留和 CMDB 状态，避免僵尸资产。

## 9. 公网暴露面

建立单独的公网资产视图：

- 域名/IP/端口/服务
- 证书
- 所属系统
- Owner
- WAF/CDN
- 最近扫描时间

**MUST：新增公网入口必须有业务原因和 Owner。**

## 10. 网络分区

根据实际情况区分办公区、研发区、测试区、生产应用区、数据库区、管理区、DMZ、安全管理区和互联网出口。

## 11. 信任边界

架构图需要标记互联网、VPN、办公/生产、应用/数据库、第三方和云/本地边界。

## 12. 南北向与东西向

南北向关注 WAF、LB、API Gateway、防火墙和 DDoS；东西向关注微服务调用、数据库访问、横向移动和服务身份。

## 13. 关键数据流

~~~text
User → WAF/LB → Web/API → Application
→ Redis/MQ → Database → Third Party
~~~

图中应标记 TLS、认证点、授权点、敏感字段、存储点和第三方传输。

## 14. 架构图要求

至少维护：

1. 总体网络拓扑
2. 生产区拓扑
3. 公网入口图
4. 核心系统数据流图
5. CI/CD 架构图
6. 日志采集图
7. 备份与灾备图

## 15. 架构变更安全评审

新增公网入口、第三方连接、敏感数据流、管理接口、云平台、大规模网络调整或新认证方案时 SHOULD 进行安全评审。

## 16. 端口、域名和证书

生产端口应记录用途、来源、目的、协议和 Owner。域名统一管理，重要 DNS 修改有审批。证书记录域名、颁发方、有效期、Owner、续期方式和私钥管理方式，并进行到期监控。

## 17. 影子资产

重点发现临时测试系统、历史子域、老公网 IP、个人创建云资源和供应商临时服务器。SHOULD 通过持续暴露面扫描发现。

## 18. 风险标签

建议使用 Internet-Facing、Critical、Sensitive-Data、Admin、Legacy、EOL、Third-Party 标签，辅助漏洞和告警优先级。

## 19. EOL 软件

资产台账应记录 OS、JDK、中间件等版本。已停止安全支持的软件进入升级计划或安全例外。

## 20. 指标

- 资产纳管率
- 公网资产纳管率
- 无 Owner 资产数
- EOL 资产数
- 未扫描资产数
- 无日志资产数
- 30 天内证书到期数
- 僵尸资产数

## 22. 落地路线

### P0
生产资产台账、公网资产清单、Owner、域名证书台账、生产网络拓扑。

### P1
自动资产发现、与漏洞/日志关联、EOL 自动识别、影子资产监控。

### P2
自动 CMDB、实时暴露面管理、资产风险评分、数据流自动发现。

## 23. 审计证据

资产台账、公网清单、网络拓扑、数据流图、新资产审批、下线记录、证书清单和端口清单。
