# 22 - 安全工程平台

> 本文档用于把安全从“安全团队发规范、研发手工遵守”演进为“研发默认使用的平台和模板天然具备安全能力”。核心目标是减少安全摩擦并让 Secure by Default 成为工程默认路径。

## 1. 目标

- 安全能力平台化。
- 开发创建项目时自动获得安全默认配置。
- 重复安全逻辑由公共组件承担。
- Security Gate 自动化。
- 安全数据统一进入平台。
- 降低每个团队自行实现认证、日志、Secret 等造成的差异。

## 2. Golden Path

Golden Path 是公司推荐且维护良好的研发标准路径。

~~~text
Project Template
   ↓
Company Parent / SDK
   ↓
CI Template
   ↓
SAST/SCA/Secret
   ↓
SBOM/Provenance
   ↓
Artifact
   ↓
Deployment Template
   ↓
Observability/Security
~~~

## 3. Company Java Parent

公司 Java Parent POM/Platform 可统一：

- JDK 版本。
- Spring Boot BOM。
- 安全依赖版本。
- Maven Plugin。
- SCA。
- Test。
- SBOM。
- Build Metadata。

## 4. Dependency Baseline

建立：

- Approved Version。
- Minimum Secure Version。
- Banned Dependency。
- Upgrade Window。

减少项目各自维护依赖版本。

## 5. Secure Starter

Spring Boot Starter 可提供：

- Authentication 集成。
- Authorization Helper。
- Audit Log。
- Trace ID。
- Error Handler。
- Security Header。
- Rate Limit Hook。
- Secret Integration。

## 6. Auth SDK

统一认证 SDK 避免：

- 每个项目自己解析 JWT。
- 忽略 issuer/audience。
- 不一致 Session。
- 自定义加密。

## 7. Authorization SDK

提供：

- RBAC。
- Data Scope。
- Object Check。
- Tenant Context。

同时避免把业务授权完全隐藏在难以审计的黑盒组件里。

## 8. Logging SDK

统一：

- JSON Log。
- Trace ID。
- User ID。
- Event Type。
- Sensitive Masking。
- Audit Event。

## 9. Error Handling

统一错误处理：

- 不返回 Stack Trace。
- Error Code。
- Trace ID。
- Internal Error Detail 仅日志。

## 10. Secret SDK

统一接入 Secret Manager/KMS，减少配置文件明文 Secret。

## 11. HTTP Client

统一 HTTP Client：

- Timeout。
- Retry。
- TLS。
- Trace。
- Metric。
- SSRF Guard（适用场景）。

## 12. File Upload Component

提供标准上传组件：

- Size。
- Type。
- Name。
- Storage。
- Malware Scan。
- Download Header。

## 13. CI Template

标准 Jenkins Library/Pipeline：

- Checkout。
- Unit Test。
- SAST。
- SCA。
- Secret Scan。
- SBOM。
- Build。
- Artifact Scan。
- Provenance。
- Gate。

## 14. Pipeline as Code

CI Template 本身：

- Git 管理。
- Code Review。
- Version。
- Release Note。
- Rollback。

## 15. Security Gate Service

统一 Gate 根据：

- Critical。
- New High。
- Secret。
- SAST。
- Artifact。
- Exception。

决定 Allow/Block。

## 16. Exception API

Gate 例外不能通过项目删除扫描步骤实现。

应有统一：

- Exception ID。
- Expiry。
- Approver。
- Reason。

## 17. Project Onboarding

新项目注册：

- Git。
- Jenkins。
- Sonar。
- SCA。
- Owner。
- CMDB。
- Log。
- Deployment。

尽量一次录入自动同步。

## 18. Project Template

新 Spring 项目默认包含：

- Parent POM。
- Security Starter。
- Dockerfile。
- Health Check。
- Logging。
- CI。
- Kubernetes Template。
- README Security Section。

## 19. Infrastructure Template

Terraform/Kubernetes 模板默认：

- Private Network。
- Secure Security Group。
- Logging。
- Backup。
- Encryption。
- Non-root。
- Resource Limit。

## 20. Secure Base Image

维护批准的：

- JDK Base Image。
- Nginx。
- Node。
- OS Minimal Image。

定期更新并通知使用项目。

## 21. Base Image Rebuild

基础镜像新 CVE 修复后，可自动识别下游项目并触发重建。

## 22. Artifact Platform

制品平台统一提供：

- Hash。
- SBOM。
- Signature。
- Provenance。
- Vulnerability。
- Retention。

## 23. SLSA

供应链成熟目标参考 SLSA v1.2：

- Build Provenance。
- Hosted Build。
- Isolated/Trusted Builder。
- Attestation。
- Verifiable Artifact。

## 24. Provenance

正式制品应逐步记录：

- Source Repo。
- Commit。
- Builder。
- Build Time。
- Dependencies。
- Artifact Digest。

## 25. Artifact Signing

成熟阶段构建系统自动签名，部署系统验证后才允许生产部署。

## 26. Ephemeral Runner

高安全项目 SHOULD 使用临时构建节点：

- 每次干净环境。
- Build 后销毁。
- 减少跨项目 Secret 残留。

## 27. Developer Environment Security

安全工程平台还应覆盖：

- IDE Plugin。
- Secret Scan。
- Dependency Advice。
- Secure Coding Rules。
- Dev Container。

## 28. Pre-commit

可提供可选 Pre-commit：

- Secret。
- Formatting。
- Basic Security。

避免过重导致开发绕过。

## 29. Security Portal

统一门户展示：

- 项目。
- Owner。
- SAST。
- SCA。
- Secret。
- Vulnerability。
- SBOM。
- Exception。
- Gate。

## 30. Developer Self-Service

研发能自行查看：

- 为什么 Gate 失败。
- 如何修复。
- 修复版本。
- 如何申请例外。
- 联系谁。

安全平台要可用，不应只显示一个红色 Fail。

## 31. Security API

所有能力 SHOULD API 化：

- Project Register。
- Scan。
- Finding。
- Exception。
- Gate。
- Asset。
- SBOM。

方便自动化集成。

## 32. Policy as Code

安全策略逐步代码化：

- Branch Protection。
- IaC。
- Kubernetes。
- Gate。
- Cloud。
- Artifact。

## 33. Detection as Code

SIEM/EDR 规则也纳入 Git、Review、Test、Deploy。

## 34. Baseline as Code

14 章节的检查项可转换为：

- Script。
- Ansible。
- OPA。
- CSPM Policy。
- K8s Policy。

## 35. Security Data Lake

成熟阶段聚合：

- Asset。
- Identity。
- Vulnerability。
- SBOM。
- Logs。
- Cloud。
- CI/CD。

建立跨域查询。

## 36. Risk Graph

进一步可形成：

~~~text
Internet Asset
   ↓
Vulnerability
   ↓
Service
   ↓
Identity
   ↓
Sensitive Data
~~~

用于实际攻击路径优先级。

## 37. Security Scorecard

对项目展示：

- Security Gate。
- Vulnerability。
- SCA。
- Logging。
- IAM。
- Backup。
- Threat Model。

Scorecard 用于改进，不宜粗暴变成绩效排名。

## 38. Platform SLO

安全平台本身也要有：

- Availability。
- Scan Latency。
- False Positive。
- Gate Latency。
- Support Response。

## 39. Version Compatibility

公共安全 SDK 升级需要：

- Semantic Version。
- Migration Guide。
- Deprecation。
- Compatibility Test。

否则团队会长期停留旧版本。

## 40. Deprecation

旧安全组件：

- 明确 EOL。
- 自动识别使用项目。
- 提供升级方案。

## 41. Security Champion Portal

为 Champion 提供：

- Training。
- Checklist。
- Threat Model。
- Finding。
- Metrics。
- Community。

## 42. Metrics

- Golden Path 覆盖率。
- Secure Starter 覆盖率。
- CI Template 覆盖率。
- 自动 Gate 覆盖率。
- 自动修复/升级项目数。
- 平均安全接入时间。
- 开发者安全平台满意度。
