# 22 - 安全工程平台

> 本文档用于把安全从“安全团队发规范、研发手工遵守”演进为“研发默认使用的平台和模板天然具备安全能力”。核心目标是减少安全摩擦并让 “默认安全”成为工程默认路径。

## 1. 目标

- 安全能力平台化。
- 开发创建项目时自动获得安全默认配置。
- 重复安全逻辑由公共组件承担。
- 安全门禁 自动化。
- 安全数据统一进入平台。
- 降低每个团队自行实现认证、日志、凭据 等造成的差异。

## 2. 黄金路径

黄金路径 是公司推荐且维护良好的研发标准路径。

~~~text
Project Template
   ↓
Company Parent / SDK
   ↓
CI Template
   ↓
SAST/SCA/凭据扫描
   ↓
SBOM/Provenance
   ↓
Artifact
   ↓
Deployment Template
   ↓
Observability/Security
~~~

## 3. 公司 Java Parent

公司 Java Parent POM/Platform 可统一：

- JDK 版本。
- Spring Boot BOM。
- 安全依赖版本。
- Maven Plugin。
- SCA。
- Test。
- SBOM。
- Build Metadata。

## 4. 依赖基线

建立：

- Approved 版本。
- Minimum Secure 版本。
- Banned Dependency。
- Upgrade Window。

减少项目各自维护依赖版本。

## 5. 安全启动组件（Starter）

Spring Boot Starter 可提供：

- Authentication 集成。
- Authorization Helper。
- 审计日志。
- Trace ID。
- Error Handler。
- Security Header。
- Rate Limit Hook。
- 凭据 Integration。

## 6. 认证 SDK

统一认证 SDK 避免：

- 每个项目自己解析 JWT。
- 忽略 issuer/audience。
- 不一致 Session。
- 自定义加密。

## 7. 授权 SDK

提供：

- RBAC。
- Data 范围。
- Object Check。
- Tenant Context。

同时避免把业务授权完全隐藏在难以审计的黑盒组件里。

## 8. 日志 SDK

统一：

- JSON Log。
- Trace ID。
- User ID。
- Event Type。
- Sensitive Masking。
- Audit Event。

## 9. 异常处理

统一错误处理：

- 不返回 Stack Trace。
- Error Code。
- Trace ID。
- Internal Error Detail 仅日志。

## 10. 凭据 SDK

统一接入凭据管理平台（Secret Manager）/KMS，减少配置文件中的明文凭据。

## 11. HTTP 客户端

统一 HTTP Client：

- Timeout。
- Retry。
- TLS。
- Trace。
- Metric。
- SSRF Guard（适用场景）。

## 12. 文件上传组件

提供标准上传组件：

- Size。
- Type。
- Name。
- Storage。
- Malware Scan。
- Download Header。

## 13. CI 模板

标准 Jenkins Library/Pipeline：

- Checkout。
- Unit Test。
- SAST。
- SCA。
- 凭据扫描（Secret Scan）。
- SBOM。
- Build。
- Artifact Scan。
- Provenance。
- Gate。

## 14. 流水线即代码

CI Template 本身：

- Git 管理。
- 代码评审。
- 版本。
- Release Note。
- Rollback。

## 15. 安全门禁服务

统一 Gate 根据：

- Critical。
- New High。
- 凭据。
- SAST。
- Artifact。
- 例外。

决定 Allow/Block。

## 16. 例外 API

Gate 例外不能通过项目删除扫描步骤实现。

应有统一：

- 例外 ID。
- Expiry。
- Approver。
- Reason。

## 17. 项目接入

新项目注册：

- Git。
- Jenkins。
- Sonar。
- SCA。
- 负责人。
- CMDB。
- Log。
- Deployment。

尽量一次录入自动同步。

## 18. 项目模板

新 Spring 项目默认包含：

- Parent POM。
- Security Starter。
- Dockerfile。
- Health Check。
- Logging。
- CI。
- Kubernetes Template。
- README Security Section。

## 19. 基础设施模板

Terraform/Kubernetes 模板默认：

- Private Network。
- Secure Security Group。
- Logging。
- Backup。
- Encryption。
- Non-root。
- Resource Limit。

## 20. 安全基础镜像

维护批准的：

- JDK Base Image。
- Nginx。
- Node。
- OS Minimal Image。

定期更新并通知使用项目。

## 21. 基础镜像重建

基础镜像新 CVE 修复后，可自动识别下游项目并触发重建。

## 22. 制品平台

制品平台统一提供：

- Hash。
- SBOM。
- Signature。
- Provenance。
- Vulnerability。
- Retention。

## 23. SLSA

供应链成熟目标参考 SLSA v1.2：

- Build Provenance。
- Hosted Build。
- Isolated/Trusted Builder。
- Attestation。
- Verifiable Artifact。

## 24. 溯源证明（Provenance）

正式制品应逐步记录：

- Source Repo。
- Commit。
- Builder。
- Build Time。
- Dependencies。
- Artifact Digest。

## 25. 制品签名

成熟阶段构建系统自动签名，部署系统验证后才允许生产部署。

## 26. 临时执行器（Ephemeral Runner）

高安全项目 SHOULD 使用临时构建节点：

- 每次干净环境。
- Build 后销毁。
- 减少跨项目 凭据 残留。

## 27. 研发环境安全

安全工程平台还应覆盖：

- IDE Plugin。
- 凭据扫描（Secret Scan）。
- Dependency Advice。
- Secure Coding Rules。
- Dev Container。

## 28. 提交前检查（Pre-commit）

可提供可选 Pre-commit：

- 凭据。
- Formatting。
- Basic Security。

避免过重导致开发绕过。

## 29. 安全门户

统一门户展示：

- 项目。
- 负责人。
- SAST。
- SCA。
- 凭据。
- Vulnerability。
- SBOM。
- 例外。
- Gate。

## 30. 研发自助服务

研发能自行查看：

- 为什么 Gate 失败。
- 如何修复。
- 修复版本。
- 如何申请例外。
- 联系谁。

安全平台要可用，不应只显示一个红色 Fail。

## 31. 安全 API

所有能力 SHOULD API 化：

- Project Register。
- Scan。
- 发现项。
- 例外。
- Gate。
- Asset。
- SBOM。

方便自动化集成。

## 32. 策略即代码

安全策略逐步代码化：

- Branch Protection。
- IaC。
- Kubernetes。
- Gate。
- Cloud。
- Artifact。

## 33. 检测即代码

SIEM/EDR 规则也纳入 Git、评审、Test、Deploy。

## 34. 基线即代码

14 章节的检查项可转换为：

- Script。
- Ansible。
- OPA。
- CSPM Policy。
- K8s Policy。

## 35. 安全数据湖

成熟阶段聚合：

- Asset。
- Identity。
- Vulnerability。
- SBOM。
- Logs。
- Cloud。
- CI/CD。

建立跨域查询。

## 36. 风险图谱

进一步可形成：

~~~text
Internet Asset
   ↓
Vulnerability
   ↓
Service
   ↓
Identity
   ↓
Sensitive Data
~~~

用于实际攻击路径优先级。

## 37. 安全计分卡

对项目展示：

- 安全门禁。
- Vulnerability。
- SCA。
- Logging。
- IAM。
- Backup。
- 威胁模型。

Scorecard 用于改进，不宜粗暴变成绩效排名。

## 38. 平台 SLO

安全平台本身也要有：

- Availability。
- Scan Latency。
- False Positive。
- Gate Latency。
- Support Response。

## 39. 版本兼容性

公共安全 SDK 升级需要：

- Semantic 版本。
- Migration Guide。
- Deprecation。
- Compatibility Test。

否则团队会长期停留旧版本。

## 40. 弃用管理

旧安全组件：

- 明确 EOL。
- 自动识别使用项目。
- 提供升级方案。

## 41. 安全倡导者门户

为 Champion 提供：

- Training。
- Checklist。
- 威胁模型。
- 发现项。
- Metrics。
- Community。

## 42. 度量

- 黄金路径覆盖率。
- Secure Starter 覆盖率。
- CI Template 覆盖率。
- 自动 Gate 覆盖率。
- 自动修复/升级项目数。
- 平均安全接入时间。
- 开发者安全平台满意度。
