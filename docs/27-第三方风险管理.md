# 27 - 第三方风险管理（TPRM）

> 本文档统一管理供应商、SaaS、外包开发、MSP、云服务、数据处理方和具有公司系统访问权限的第三方。

## 1. 目标

- 采购前识别风险。
- 按风险而不是统一问卷管理供应商。
- 合同明确关键安全责任。
- 第三方访问与数据最小化。
- 合作期间持续复审。
- 事件发生时有通知和处置机制。
- 合同结束后完成账号、数据和连接退出。

## 2. 第三方分类

- SaaS。
- Cloud Provider。
- MSP/MSSP。
- 外包开发。
- 软件供应商。
- Data Processor。
- API Partner。
- 咨询/运维人员。
- 硬件/网络服务商。

## 3. Risk Tier

### Tier 1 - Critical
满足任一：
- 管理生产。
- 访问核心数据。
- 处理大量敏感数据。
- 供应链影响多个产品。
- 关键业务强依赖。

### Tier 2 - High
有限生产/敏感数据访问或重要业务依赖。

### Tier 3 - Standard
低敏感、无生产高权限。

## 4. Pre-Purchase Assessment

采购前收集：

- 服务描述。
- 数据范围。
- 网络/权限。
- 部署位置。
- 安全认证/报告。
- 漏洞管理。
- Incident Response。
- BCP/DR。
- Subprocessor。
- Secure Development。
- EOL/Patch。

## 5. Evidence

根据风险可要求：

- SOC 2/ISO 等报告（如适用）。
- Pentest Summary。
- Security Whitepaper。
- Architecture。
- BCP Test。
- Vulnerability Policy。
- Privacy Documents。

不能机械认为有认证就等于风险可接受。

## 6. Security Questionnaire

问卷按 Tier 裁剪。

避免对所有供应商发数百题问卷造成形式主义。

## 7. Technical Validation

高风险 SaaS/产品可额外：

- SSO/SAML 测试。
- MFA。
- API Token。
- Log Export。
- Security Config Review。
- External Exposure Review。

## 8. Contract

重要合同 SHOULD 明确：

- Security Responsibility。
- Data Use。
- Access Control。
- Vulnerability Fix。
- Incident Notification。
- Subprocessor。
- Backup/BCP。
- Data Return/Delete。
- Audit/Evidence。
- Termination。

具体条款由法务确认。

## 9. Incident Notification

高风险供应商合同应明确安全事件通知时限或合理的及时通知责任。

## 10. Vulnerability

供应商软件出现 Critical 漏洞：

- 获取 Advisory。
- 影响版本。
- 修复版本。
- Workaround。
- 发布时间。
- 公司暴露面。

## 11. Access

第三方账号：

- 实名。
- 一人一号。
- MFA（高风险）。
- 最小权限。
- 有效期。
- Owner。
- 日志。

## 12. Remote Support

远程支持：

- 按需开通。
- 时间限制。
- 受控终端/通道。
- 操作记录。
- 完成后回收。

## 13. Data Sharing

只共享完成目的所需的数据。

建立：

- 字段。
- 数据量。
- 频率。
- 加密。
- Retention。
- Deletion。

## 14. SaaS

重点检查：

- SSO/MFA。
- Admin。
- OAuth。
- External Sharing。
- Audit Log。
- Backup/Export。
- Offboarding。

## 15. Shadow SaaS

SHOULD 发现未采购/未审批 SaaS。

可通过：

- SSO。
- Proxy。
- Expense。
- CASB 类能力。
- OAuth App。

## 16. Concentration Risk

避免多个关键业务都依赖同一不可替代供应商而没有连续性方案。

## 17. Subprocessor

关键供应商使用分包商/子处理方时，关注其对公司数据和关键服务的影响。

## 18. Continuous Monitoring

Tier 1/2 定期关注：

- 重大漏洞。
- Security Incident。
- 域名/证书。
- 外部暴露。
- 合规报告变化。
- 财务/服务连续性风险（由相关部门评估）。

## 19. Annual Review

复审：

- 服务是否仍需要。
- 数据是否变化。
- 权限是否扩大。
- 是否发生 Incident。
- 合同是否到期。
- 安全能力是否变化。

## 20. Offboarding

合作结束：

1. 禁用账号。
2. 回收 Token/Key。
3. 关闭 VPN/专线。
4. 数据返还/删除。
5. 终止 API。
6. 取消 OAuth。
7. 更新 CMDB/合同状态。
8. 保留必要审计证据。

## 21. Third-party Incident

供应商发生 Incident：

- 确认公司是否受影响。
- 吊销访问。
- 轮换共享 Secret。
- 查询公司日志。
- 评估数据。
- 跟踪供应商 RCA。
- 必要时启动公司 IR。

## 22. Exceptions

业务必须使用但风险未满足时：

- 明确 Gap。
- 补偿控制。
- Owner。
- 风险接受。
- 有效期。
- 退出/替代计划。

## 23. Metrics

- Tier 1/2 供应商数量。
- 上线前评估覆盖率。
- 超期复审数。
- 超期第三方账号。
- 无合同安全条款高风险供应商数。
- 供应商 Incident 数。
- Offboarding 未完成数。
