# 安全现状与目标画像

> 本文档用于区分“文档已经定义”与“公司真实已经实施”。Current 必须基于真实证据评估，不能因为规范中写了某项要求就判断为已实施。

## 1. 成熟度等级

| Level | 定义 |
|---|---|
| L0 | 未建立或主要依赖个人经验 |
| L1 | 有基础控制、人工执行，可重复性有限 |
| L2 | 已标准化、覆盖主要范围、可度量，部分自动化 |
| L3 | 默认安全、平台化、持续验证、自动证据与风险闭环 |

## 2. 现状评估证据至少引用一种真实证据：配置导出、CMDB、IAM/MFA 报告、扫描、CI/CD、SIEM/EDR、工单、演练、备份恢复或审计抽样。

## 4. 差距改进路线图

每个 Gap 至少记录：Gap ID、Domain、Current、Target、风险、Priority、负责人、Accountable、Target Date、证据和状态。

## 5. 升级路径

### L0 → L1
负责人、制度、基础工具、人工流程、关键资产覆盖。

### L1 → L2
统一 Standard、自动扫描、覆盖率、SLA、看板、证据、定期复审。

### L2 → L3
黄金路径、Policy as Code、Continuous Validation、JIT/零信任、Trusted Build、风险 Graph、自动闭环。

## 6. 第一轮评估顺序

P0：资产、IAM、终端、网络、AppSec、DevSecOps、漏洞、备份恢复、邮件安全。

第二批：SOC、威胁建模、Cloud、Crypto、Data/Privacy、TPRM、BCP。

第三批：零信任 深化、紫队、产品安全、PSIRT、Security Platform、AI/Mobile。

1. 当前安全画像。

6. 成熟度变化。
7. 管理层风险接受。
