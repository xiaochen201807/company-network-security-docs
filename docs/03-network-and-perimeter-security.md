# 03 - 网络与边界安全

> 本文档规范公司网络区域、边界访问、防火墙、VPN、DNS、互联网出口、管理面、公网暴露和网络安全审计。

## 1. 目标

- 降低公网攻击面。
- 限制攻击者横向移动。
- 控制跨安全区域访问。
- 远程访问可认证、可授权、可追溯。
- 网络变更可审批、可验证、可回退。
- 异常流量具备检测能力。

## 2. 基本原则

### 2.1 默认拒绝
跨安全区域访问默认拒绝，按业务最小化开放。

### 2.2 最小开放
规则必须尽量限定 Source、Destination、Protocol、Port、Purpose 和 Owner。

### 2.3 管理面隔离
管理端口与业务端口尽量分离，管理面不直接暴露公网。

### 2.4 生产隔离
办公、开发和测试环境不得无控制直接进入生产核心区域。

## 3. 网络区域

根据公司实际定义：

- Internet
- DMZ
- 办公网
- 研发区
- 测试区
- 生产应用区
- 数据库区
- 管理区
- 安全管理区

跨区访问通过防火墙/ACL 等显式控制。

## 4. 防火墙策略管理

### 4.1 新增规则
申请至少包含：

- 申请人
- 源地址/网段
- 目的地址/网段
- 协议/端口
- 业务用途
- 系统 Owner
- 是否临时
- 到期日期

### 4.2 高风险规则
重点检查：

- any → any
- 0.0.0.0/0 → SSH/RDP/管理口
- 办公网 → 核心数据库
- Internet → Redis/MySQL/Elasticsearch/Jenkins
- 大网段长期互通

### 4.3 临时规则
**MUST：临时规则必须有到期时间。**

### 4.4 定期复审
至少季度 Review 无流量、无 Owner、过期、重复、过宽规则。

## 5. 公网暴露

公网原则上只开放业务必需端口。

以下服务默认不应直接公网暴露：

- SSH
- RDP
- MySQL/PostgreSQL
- Redis
- Elasticsearch
- Jenkins
- Kubernetes API
- 内部管理后台

如果确需开放，必须有强化认证、来源限制、日志和风险审批。

## 6. VPN 与远程访问

### 6.1 账号
一人一号，禁止共享；外包账号设置有效期；离职及时回收。

### 6.2 认证
关键远程访问 SHOULD 启用 MFA。

### 6.3 授权
VPN 接入不等于获得整个内网权限，应按用户/角色/目标网段/端口限制。

### 6.4 日志
至少保留用户、登录时间、源 IP、成功/失败、断开时间和可用的设备信息。

## 7. 生产管理访问

生产 SSH、RDP、数据库和管理控制台 SHOULD 通过 VPN、堡垒机、PAM 或管理网访问，禁止无保护公网直接管理。

## 8. SSH 基线

- 禁止弱口令。
- 优先密钥或统一身份认证。
- 限制 root 直接登录。
- 限制来源地址。
- 记录成功/失败登录和 sudo 行为。

## 9. RDP 基线

- 不公网直接暴露。
- 通过 VPN/堡垒机。
- 使用强认证。
- 管理员账号最小化。
- 记录登录。

## 10. 数据库与中间件网络

数据库、Redis、Elasticsearch、MQ 等生产服务：

- MUST 不无保护暴露公网。
- 只允许必要应用和管理来源。
- 办公网访问按需审批。
- 管理端口使用受控路径。
- 无认证或默认口令视为高风险。

## 11. WAF

WAF 用于增强公网 Web/API 防护，但不能替代应用修复。WAF 新规则应测试、灰度、监控误报并准备回退。

## 12. API Gateway

可集中承担 TLS、认证入口、路由、Rate Limit、IP 控制和日志，但业务对象级/功能级授权仍应由应用正确执行。

## 13. DNS 与域名

- 域名统一管理。
- 重要 DNS 变更有审批与复核。
- 废弃子域及时清理。
- 内部关键服务避免依赖不可控的外部解析。
- 监控异常解析与域名劫持风险。

## 14. TLS 与证书

公网 Web/API SHOULD 使用 TLS。禁用已知不安全协议，私钥受控，证书提前续期并监控到期。

## 15. 互联网出口

生产服务器访问互联网按需开放。数据库、核心中间件、构建和管理服务器的出口应重点限制。

如使用统一代理，应记录来源、控制目的域名并保留必要审计。

## 16. DNS 与 C2 检测

重点检测：

- 大量 NXDOMAIN
- 随机长子域
- 异常 DNS 服务器
- 已知恶意域名/IP
- 周期性 Beacon
- 服务器异常外连

## 17. 横向扫描检测

关注：

- 单主机扫描大量端口
- 单主机探测大量内部 IP
- SMB/RDP/SSH 批量探测

公司授权扫描器应明确 IP/账号并在检测系统中可识别。

## 18. 网络设备安全

防火墙、交换机、路由器：

- 管理账号实名。
- 修改默认口令。
- 管理面限制来源。
- 配置定期备份。
- 时间同步。
- 日志集中。
- 固件/系统及时安全更新。

## 19. SNMP

如果使用 SNMP：

- 避免默认 community。
- 优先使用安全版本。
- 限制管理来源。
- 不公网暴露。

## 20. 无线网络

办公无线应强认证；访客网络与内网隔离；访客不得直接访问生产区域；无线管理界面仅允许受控管理网访问。

## 21. 第三方专线/VPN

必须明确用途、源/目的网段、端口、Owner、有效期/复审周期和日志。合作终止后及时关闭。

## 22. 网络变更流程

~~~text
申请 → 风险评估 → 审批 → 实施
→ 连通性验证 → 安全验证 → 观察 → 关闭
~~~

高风险变更必须准备回退。紧急变更可简化前置流程，但必须记录原因、控制范围、事后补审并回收临时策略。

## 23. 应采集的网络日志

优先：

- Firewall
- WAF
- VPN
- DNS
- Proxy
- LB/API Gateway
- 网络设备管理日志

## 24. 检测场景

- 公网扫描
- VPN 暴力破解/异常登录
- 新增高危公网端口
- 横向扫描
- C2/异常外连
- DNS 隧道特征
- 大量连接失败
- 异常数据外传
- 防火墙策略异常变化

## 25. 指标

- 公网端口数量
- 高风险公网端口数量
- any-any 规则数量
- 过期临时规则数量
- 无 Owner 规则数量
- VPN MFA 覆盖率
- 防火墙规则复审率

## 27. 落地路线

### P0
清理公网管理端口和数据库、中间件；VPN 一人一号；防火墙规则 Owner；临时规则到期；数据库区隔离。

### P1
VPN MFA、堡垒机/PAM、DNS/Proxy 日志集中、东西向检测、网络策略自动复审。

### P2
微隔离、ZTNA、网络行为分析、策略即代码。

## 28. 审计证据

网络拓扑、防火墙规则、变更工单、VPN 用户清单与日志、第三方连接清单、公网暴露报告。
